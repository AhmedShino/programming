# مَسار | منصة تعلّم البرمجة الشخصية

نسخة أولية قابلة للتجربة على الهاتف والكمبيوتر. واجهة عربية RTL وبتصميم داكن.

## الموجود حاليًا
- أسئلة بداية متعددة الاختيارات لتحديد الأهداف والمستوى والوقت وأسلوب التعلم.
- مسار تعلّم مبدئي ومراحل قابلة للتتبع.
- حصة يومية فيها شرح ومثال كود وسؤال واختيارات وتغذية راجعة.
- تدريب إضافي ومراجعة، ومؤقّت يمكن تشغيله وإيقافه.
- تحديد وقت يومي من 10 إلى 60 دقيقة.
- حفظ التقدم محليًا في المتصفح باستخدام `localStorage`.
- واجهة مساعد تجريبية مع نقطة اتصال جاهزة لخادم AI.
- خادم Cloudflare Worker اختياري لإبقاء مفتاح API خارج ملفات الواجهة.

## مهم قبل النشر
هذه **نسخة تجريبية شخصية** وليست نظام حسابات متعدد المستخدمين بعد. التقدم محفوظ على نفس المتصفح والجهاز فقط. لا يوجد تسجيل دخول أو مزامنة بين الأجهزة أو لوحة إدارة. ولا تضع مفتاح API في `app.js` أو `index.html` أو أي ملف ترفعه إلى GitHub.

## التجربة على جهازك
1. فك ضغط الملف.
2. افتح `index.html` في متصفح حديث. بعض ميزات المتصفح مثل النسخ قد تتطلب تشغيل الموقع عبر خادم محلي.
3. لتجربة أقرب للنشر، ارفع الملفات الثلاثة `index.html` و`styles.css` و`app.js` إلى مستودع GitHub، ثم فعّل GitHub Pages من Settings → Pages → Deploy from a branch → `main` → `/ (root)`.

## تفعيل مساعد AI بأمان (اختياري)
الملف `worker/index.js` مثال لخادم Cloudflare Worker. لا يعمل تلقائيًا على GitHub Pages؛ يجب نشره كخدمة منفصلة.

1. أنشئ Worker في Cloudflare وانسخ محتوى `worker/index.js`.
2. في إعدادات Worker، أضف Secret باسم `OPENAI_API_KEY` يحتوي مفتاح API الخاص بك. لا تشارك المفتاح ولا تضعه في الواجهة.
3. أضف متغيرًا اختياريًا `OPENAI_MODEL` مثل `gpt-4.1-mini`.
4. عيّن `ALLOWED_ORIGIN` إلى عنوان موقعك الفعلي بدل `*` قبل الاستخدام الجاد.
5. عدّل في `app.js` عنوان `fetch('/api/coach', ...)` إلى عنوان الـ Worker الكامل، أو اربط نطاقًا مخصصًا بحيث يكون المسار `/api/coach` متاحًا من نفس الأصل.
6. جرّب الطلب. قد تحتاج إلى ضبط CORS حسب عنوان موقعك، وإضافة حدود للاستخدام لمنع الاستهلاك غير المقصود.

## حدود النسخة الحالية
- الخطة والمسارات والأسئلة المدمجة أمثلة أولية، وليست منهجًا كاملًا أو توصية شخصية مولّدة بالذكاء الاصطناعي.
- المساعد يرسل الطلب إلى الخادم عند توفره، وإذا لم يتوفر يرجع إلى ردود تجريبية محدودة.
- لا يوجد تنفيذ آمن للكود داخل المتصفح حاليًا. لا تشغّل كودًا غير موثوق على الخادم دون عزل مناسب.
- تسجيل الدخول الحقيقي وحفظ التقدم على عدة أجهزة يحتاجان Backend وقاعدة بيانات ومصادقة (مثل Supabase أو خدمة مماثلة).
- لا توجد إشعارات تذكير يومية في هذه النسخة.
- المؤقّت يعمل بينما الصفحة مفتوحة فقط، ولا يضمن تشغيل تنبيه إذا أغلق المتصفح الصفحة.

## الخطوات المقترحة بعد التجربة
1. التأكد من تدفق أسئلة البداية وسهولة الاستخدام على الهاتف.
2. تطوير نظام الدروس والتمارين والمراجعة المتباعدة.
3. ربط المساعد الذكي بالخادم وإضافة زر «حوّل هدفي إلى خطة».
4. إضافة تسجيل دخول وقاعدة بيانات عند الحاجة لمزامنة التقدم.
5. إضافة محرر كود آمن باستخدام مزوّد تشغيل معزول أو بيئة تعليمية مناسبة.
6. تحويل الموقع إلى PWA أو تطبيق Capacitor بعد استقرار تجربة الويب.

## الملفات
- `index.html`: بنية الواجهة.
- `styles.css`: التصميم المتجاوب.
- `app.js`: التنقل، أسئلة البداية، الحصة، التدريب والحفظ المحلي.
- `worker/index.js`: مثال Worker لخدمة AI.
